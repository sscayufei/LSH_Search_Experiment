## 理论推导与搜索范围

随机超平面单 bit 碰撞概率 p(s)=1-acos(s)/pi；k bit 同表概率 p(s)^k；L 表候选概率：

```text
P(s;k,L) = 1 - (1 - p(s)^k)^L
L_min = ceil(log(1-target) / log(1-p(s)^k))
```

取 s1=tau=0.75，s0=0 为明确正交的无关参考点，目标 P(s1)≥0.90。
s0=0 不是声称真实背景向量全部正交，实际随机参考对分布已另报。

一组数值推导（理论值）：

- p(0.75)=0.7699465438，p(0.75)^12=0.0434037133。
- k=12、L=16：P(s1)=0.5083465951；L=32：P(s1)=0.7582769294。
- k=12 达到边界理论目标 0.90 至少需要 L=52；本次预定网格最高为 32。
- s0=0 时 p=0.5；k=12、L=32：P(s0)=0.0077830081。
- 若 10,000 条背景向量均满足这一条件模型，期望误候选约 77.83；这是条件化理论值，不是实测候选数。

达到同一理论边界目标，k=8/12/16 分别需要 L≥18/52/150。
因此用推荐网格 k={8,12,16}、L={4,8,16,32} 检查由高碰撞/多候选到低碰撞/少候选的范围。
k 增大使 p^k 降低，通常减少候选并损失召回；L 增大提高候选命中概率，同时增加查表、ID 引用与内存。
理论值保存于 theory_grid.csv，没有被写成实际 Recall。

## 计时、内存口径与复杂度

固定 seed，底层线程限制为 1；每配置完整预编码语义查询热身 1 轮、测量 3 轮，共 1,800 条计时样本。
API 外部 perf_counter 计时包含查询归一化、签名、查桶/去重/排序、候选精筛及 API 统计开销。
不包含数据加载/编码、全库 Ground Truth、正确性检查、建索引、内存遍历或绘图。
每查询平均 3 次计时，表中均值/P95 对 50 条查询的平均耗时再统计；不是三方法最终性能对照。
线程库具体状态保存在 phase4_manifest.json。时延受运行环境影响，可复现的是测量方法和输入，不保证每次数字相同。

内存使用 sys.getsizeof 递归估算唯一可达对象：超平面数组及数据缓冲、桶列表/字典、签名键、ID 元组及整数。
用对象 id 集合避免共享对象重复计数；拥有缓冲的 NumPy 数组不额外重复加 nbytes，视图则追溯 base。
排除共享历史向量工作矩阵，不包含 Exact Hash 索引；不是 RSS、峰值内存或操作系统分配器的完整计量。
不同 k 下桶占用数和字典开销不同，所以更多 bit 未必节省 Python 索引空间。

主流程新增算法成本：

- 验证 Ground Truth：O(QNd) 时间，完整得分 O(QN) 空间。
- 来源/随机参考分布：当前实现每查询构造非来源 ID 集，约 O(QN)，保存采样对 O(Qm+S)，m=100、S 为来源对数量。
- G 组网格：建表求和 O(sum(NLkd))，测量查询约 O(sum(QR(Lkd+B+c log c+cd)))，R 为重复次数。
- 内存估算遍历额外索引对象约 O(Lkd+NL)；不同配置依次处理，不同时保留全部索引。
- Pareto 前沿采用两两支配检查 O(G²)，G=12 时简单且足够；选择排序键固定，不受计时噪声影响。
